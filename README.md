# Weather AI Pet

A small weather app: search any city (or use your GPS location) to see the current
conditions, plus a short, witty tip generated by AI based on that weather. Built as a
learning project — vanilla React + Express, no framework starter, no UI kit.

## Features

- Search weather by city name or by browser geolocation
- Live weather data via OpenWeatherMap: temperature (°C/°F toggle), "feels like",
  humidity, wind, description and icon
- AI-generated advice/tip via the Google Gemini API, based on the current weather
  (with retry-on-overload and short-lived caching)
- UA / EN interface language toggle
- Search history and favorite cities, persisted in `localStorage` via a reusable
  `useLocalStorage` hook
- Glassmorphism UI styled with SASS (shared variables + mixins)
- Dockerized backend: `Dockerfile` for a production image, `docker-compose.yml` for
  local development with hot reload

## Tech stack

- **Frontend:** React 19, Vite, SASS
- **Backend:** Node.js, Express 5
- **External APIs:** OpenWeatherMap (current weather), Google Gemini (`@google/genai`)
  for advice generation
- **Tooling:** Docker, Docker Compose

## Running locally (without Docker)

**Backend:**

```bash
cd server
cp .env.example .env   # fill in OPENWEATHER_API_KEY and GEMINI_API_KEY
npm install
npm run dev             # http://localhost:4000
```

**Frontend** (in a second terminal):

```bash
cd client
cp .env.example .env   # VITE_API_URL=http://localhost:4000 by default
npm install
npm run dev             # http://localhost:5173
```

## Running the backend with Docker

Build and run the production image directly:

```bash
docker build -t weather-ai-pet-server ./server
docker run --rm -p 4000:4000 --env-file server/.env weather-ai-pet-server
```

Or, for local development with hot reload (code is live-mounted, nodemon restarts on
change):

```bash
docker compose up --build
```

Either way the API is available at `http://localhost:4000`. The frontend still runs
separately with `npm run dev` in `client/` — it doesn't need Docker.

## Environment variables

**`server/.env`**

| Variable              | Description                                   |
| ---------------------- | --------------------------------------------- |
| `PORT`                 | Backend port (default `4000`)                 |
| `OPENWEATHER_API_KEY`  | API key from [openweathermap.org](https://openweathermap.org/api) |
| `GEMINI_API_KEY`       | API key from [Google AI Studio](https://aistudio.google.com/) |

**`client/.env`**

| Variable        | Description                                         |
| ---------------- | ----------------------------------------------------- |
| `VITE_API_URL`   | Base URL of the backend (default `http://localhost:4000`) |

Neither `.env` file is committed — see `.env.example` in each folder for the expected
keys.

## API endpoints (backend)

| Method | Path           | Description                                                          |
| ------ | -------------- | ---------------------------------------------------------------------- |
| GET    | `/api/health`  | Health check — `{ "status": "ok" }`                                   |
| GET    | `/api/weather` | Current weather. Query: `city=<name>` **or** `lat=<>&lon=<>`, plus `lang=uk\|en` |
| POST   | `/api/advice`  | AI tip for given weather. Body: `{ city, temperature, description, isDaytime, localTime, language }` → `{ advice }` |
